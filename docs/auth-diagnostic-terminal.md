# Recovering localhost authentication diagnostics

Inspected 24 October 2026 (Africa/Douala). No server was restarted or terminated.
No real invitation token, hosted account or Auth configuration was changed.

## Process and output location

Port 3000 was owned by `node.exe` PID **24288**, bound to `127.0.0.1`.
Its Next.js parent was PID 20676; the hosted-test launcher was PID 1728,
running under the agent's command session, not a VS Code integrated terminal.
Process IDs are inspection-time observations and can change after a restart.

The launcher pipes child stdout/stderr, forwards only whitelisted authentication
labels to its own stdout and discards other output. That stdout was captured by
the agent tool session (session 87859), explaining why no VS Code terminal was
visible. Earlier launcher versions discarded child output entirely; the currently
running version retained the latest failure label. Next.js also captured it in
`.next/dev/logs/next-development.log`, which is generated, ignored and subject to
rotation. This file may contain unrelated sensitive entries: do not print, share
or tail it directly.

## Recovered failure

The latest captured submission emitted:

```text
[elapsed 00:11:44.846] auth_confirmation form_received
[elapsed 00:11:44.846] auth_confirmation origin_rejected
```

These are elapsed log timestamps, not wall-clock times. Older pairs at elapsed
00:00:17 and 00:05:29 are known malformed diagnostic probes. No subsequent real
submission was generated by this investigation.

`origin_rejected` is returned before form parsing, client creation, store checks
or `verifyOtp`. Thus this captured failure did not reach Supabase token
verification or consume its token. The comparison rejects a missing, malformed
or mismatched Origin. The exact mismatch was not captured and must not be guessed
or "fixed" by bypassing the same-origin check. This evidence does not retroactively
identify the cause of the original attempt before diagnostic logging existed.

## View safely in VS Code without restarting the server

Open **Terminal > New Terminal** in this repository, then run:

```powershell
npm run auth:hosted:logs
```

The viewer replays retained safe labels and follows new local log entries. It
prints only exact whitelisted server events and validated elapsed timestamps;
it rejects browser logs, arbitrary messages, extra text and malformed records.
It understands Next.js's quoted console-argument serialization. It never loads
dotenv files, contacts Supabase, controls the server or submits a token.
Ctrl+C stops this viewer only. For a one-time read use:

```powershell
npm run auth:hosted:logs -- --once
```

No server restart is necessary for this viewer. A later approved move of the
server itself into VS Code requires stopping only the verified existing launcher
and running `npm run auth:hosted:dev` there; do not start a competing server while
port 3000 is occupied. The launcher now prints the viewer command on future
starts. No process redirection can attach the existing stdout pipe to a newly
opened integrated terminal, so use the viewer for the running instance.
